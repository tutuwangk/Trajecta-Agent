# 电脑端交互体验优化 · 2026-10-03

本次采用 Finesse UI 的表单、运行记录与动效指导，参考用户指定的
[Wanderlog](https://wanderlog.com/en)。新建行程使用双栏表单与旅行预览卡，突出目的地、日期和旅行想法。日期字段初始为空，选择日期后显示值。
按用户追加要求删除预览卡中的“一点期待，一段新旅程”文字，以及行程底部的“未安排”区块。较矮的电脑窗口使用紧凑标题和表单间距。

开始规划、体验示例、偏好、日期切换、地点选择与调整抽屉加入鼠标和按压反馈。
动效使用 CSS 的 transform 与 opacity；系统要求减少动态效果时，控件直接显示最终状态。
示例入口的旅行天数从本地示例数据读取。

工作面板每 1.5 秒增量读取当前 run 的 events。记录按 event_id 合并，恢复时重新读取并去重。
运行状态与交付继续读取原接口。事件连接失败会保留已读取记录，并提供重新连接操作。
开始新的运行时，旧事件会清空。

根 Agent 的工具执行边界记录 tool_started 与 tool_finished。每次调用有独立 call_id，
记录工具名、地点查询对象、少量上下文字段、执行结果与 perf_counter 测得的耗时。
完整行程入参和模型内部推理继续由原运行链管理。资料理解和模型请求也有对应工作事件。
工具异常及结构化修正继续遵循原执行语义；本次加入的记录用于界面呈现。

界面显示当前工作、并行调用、工具展开记录、累计运行用时和停止按钮。
累计用时根据 run_started 和暂停、等待确认、终态事件计算，扣除等待用户的时间。
运行完成后，行程地图页面可展开规划记录。读取历史记录时保留滚动位置，用户可回到最新动态。

发布继续使用 V3 原有候选、评估和 Release 流程。界面在活跃规划期间显示工作面板，
终态或需要确认的候选继续使用原有交付组件。
