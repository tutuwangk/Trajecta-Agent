# 2026-10-03 行程交付与产品展示修正

根因是营业资料完整性、执行冲突和用户页面共用同一条失败路径。此次修改将资料可用性纳入统一的 `fact_policy.py`：来源缺失、普通资料不足和提取服务失败允许生成 Release；明确闭馆、营业时间冲突、地点身份错误、路线缺口和固定预约冲突继续由 Agent 调整。

运营信息采用高德详情或检索返回的内容。常规每日、每周营业安排直接适用；移除模型置信度阈值。已检索到运营信息但完整时段未知时，保存 `visit_compatible=null`，候选保留 `fact_status=degraded` 并允许发布。高德已有营业信息时省去重复网页查询；提取服务不可用时保留原始高德营业时间。资料查询仍有每地点两次搜索、两页正文的上限。

最终产品页删除 Assessment、FactGap、核验状态、诊断提示和规划记录模块。地图、每日时间轴、地点信息及当前日期的来源预约事项继续展示。操作失败使用与当前动作对应的简短提示，服务端原始错误内容保留在内部。Release 摘要移除门禁与需求闭环统计。
