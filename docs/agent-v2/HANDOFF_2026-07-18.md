# Agent V2 项目交接

日期：2026-07-18

当前提交：`d689a47`

范围：2026-07-18 本项目的方案审查、WP0～WP8 验收与 R0～R4 修复会话。

## 当前结论

Trajecta 已在同一仓库建立隔离的 Agent V2：用户原始需求直接创建 `TripWorkspace` 与有限生命周期
`AgentRun`，唯一根 `TripPlannerAgent` 自主选择工具、维护草案、模拟并提交候选。Legacy 仍保留作
shadow 对照和历史只读，不是 V2 内部 fallback。

WP0～WP7 已完成。WP8 首次验收不通过，原因不是本地测试失败，而是真实多日酒店场景暴露同一
模型回复内多个 mutation 共享旧版本令牌，最终形成 stale-version 和未处理异常；评测设施同时缺少
首次错误率、可续跑 checkpoint、30 次批量统计、shadow 和盲测证据。

R0～R4 已修复并通过真实多日酒店回归。当前仍不允许切流或删除 Legacy，因为 30 次真实全链、
V2/Legacy shadow、匿名盲测与至少 7 天稳定期尚未完成。

## 已确认的长期产品决策

- 取消“识别 POI → 人工确认 → 才能规划”的强制 wizard。
- 生产只有一个具有旅行决策权的根 Agent；V4 Flash 是无目标、无长期记忆、无写权限的结构化工具。
- 事实、身份、坐标、路线、时间算术、版本、幂等和发布资格归确定性系统。
- 只有事实不变量与用户明确不可调整的承诺能够阻止发布。
- 强度、普通饭点、推荐时段、超长游览日、区域均衡和普通偏好属于 experience issue。
- 不使用 deterministic itinerary fallback；最小条件无法闭合时返回保留有效 Workspace 的
  `incomplete`。
- 运行中不接受用户主动修改；Agent 澄清继续原 run，发布后修改创建 revision run。
- 第一阶段记忆只限当前 TripWorkspace；不自动建立跨旅行偏好。

## 今日实施路径

### 方案与 WP0～WP3

- 用 ADR 固化根 Agent 控制边界、Workspace/Run/Release、最小硬约束、DeepSeek/Harness 和
  Temporal-ready 决策。
- 完成 DeepSeek V4 thinking、多轮工具、reasoning transcript、StepPersistence 和 Deferred Tool
  合同验证。
- 建立隔离的 `backend/app/trip_agent/` 领域、仓储、Runtime 和 import boundary。
- 完成“原始输入 → 工具循环 → Draft → Compiler → Candidate → Release”的纵向闭环。

### WP4～WP7

- 完成地点提及、真实高德候选、父子实体守卫、来源/Claim、批量路线和游览画像工具。
- 完成 WorkingDraft、高语义 mutation、确定性 Compiler、最小 ReleaseGate 和受限 Narrative。
- 完成 provider transcript、业务状态、澄清、答案、revision、发布和终态的持久化/恢复边界。
- 完成 `/api/v2` 与 AI-Native 首页、进度、Workspace、批量澄清、刷新恢复和 revision UI。

### WP8 首次验收

- 本地基线通过，但首次生产 V4 Flash mention 运行出现 8/100 provider errors，按首次失败计分的
  recall 为 91.14%，未达到 95% Gate。
- 单日 V2 实链发布成功。
- 多日酒店实链因两个 `estimate_visit_profile` 调用共享旧 `expected_version` 而失败；该错误否决
  “30 次真实全链无未处理异常”。
- 当时不存在足以完成 30 次统计、同输入 shadow 和匿名盲测的可审计运行器。

### R0～R4 修复

- 模型工具 schema 不再暴露 `expected_version`；Runtime 每次执行读取当前版本，Repository 继续 CAS。
- 增加 `estimate_visit_profiles` 批量 mutation 和基于 `run_id + tool_call_id` 的 tool-effect 复用。
- 重复、收敛预留和无进展改为 `tool_unavailable_in_convergence` 软反馈；只有绝对墙钟硬停止。
- 可恢复 action/output repair exhaustion 收敛为诊断明确的 `incomplete`，不抛到 API/脚本外。
- 推荐时段与超长游览日改为非阻断 experience issue；高召回 hypothesis 不再默认全部必须解析。
- Live eval 增加逐 case checkpoint、`--resume`、首次错误率和恢复统计。
- 新增持久化 WP8 runner、shadow pair 与匿名 A/B 盲测包生成器。

## 已知剩余风险

- 领域 mutation 与 tool-effect journal 尚未处于同一数据库事务；存在极窄的“mutation 已提交、journal
  未写入即崩溃”窗口。
- Provider request/token 完整账本尚未跨恢复累积；当前持久化的是墙钟、工具签名与进展状态。
- V4 Flash 当前稳定性 Gate 未通过，不能用失败 case 重跑成功覆盖首次错误。
- 单次真实发布只证明阻断故障已修复，不证明 30 次分布和盲测 Gate 达标。
